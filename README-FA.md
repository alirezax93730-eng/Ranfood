# ران‌فود — نسخه اولیه وب‌اپ چنددستگاهی

این پروژه یک **نسخه اولیه قابل اجرا (MVP)** از وب‌اپ ران‌فود است و به پروژه Supabase موجود شما وصل می‌شود. با میزبانی روی یک سرویس وب، چند گوشی و آیپد می‌توانند هم‌زمان از یک دیتابیس استفاده کنند.

## ۱) اتصال به Supabase
1. فایل `config.js` را باز کن.
2. مقدار `SUPABASE_ANON_KEY` را با **کلید عمومی جدید** پروژه جایگزین کن.
3. هرگز کلید `service_role` را در این پروژه قرار نده.
4. آدرس پروژه از قبل روی پروژه RanFood تنظیم شده است.

## ۲) اجرا و انتشار
برای آزمایش، فایل‌ها را روی یک میزبان استاتیک مثل Netlify یا Cloudflare Pages بارگذاری کن. پوشه اصلی همین پروژه است؛ دستور ساخت (build) لازم ندارد.
برای استفاده چنددستگاهی، باید سایت روی HTTPS منتشر شود. سپس در مرورگر گوشی گزینه Add to Home Screen / افزودن به صفحه اصلی را بزن.
این نسخه برای کارکرد کامل به اینترنت نیاز دارد.

## ۳) حساب‌ها و نقش‌ها
ثبت‌نام عمومی فقط مشتری می‌سازد. نقش مدیر کل، مدیر رستوران، کارمند و پیک باید امن و از سمت مدیر سیستم در جدول `profiles` تعیین شود؛ نقش را از فرم عمومی دریافت نکن.
برای ایجاد مدیر کل، ابتدا همان کاربر را از صفحه ثبت‌نام بساز، سپس از SQL Editor با شناسه Auth کاربر، نقش او را به `super_admin` تغییر بده. این کار را فقط خود مالک پروژه انجام دهد.

## ۴) قابلیت‌های موجود در این نسخه
- ورود و ثبت‌نام با Supabase Auth (ایمیل و رمز عبور)
- نمایش رستوران‌ها، شعبه‌ها و منوی فعال
- سبد خرید ساده
- ثبت سفارش از طریق تابع امن `create_ranfood_order`
- نمایش سفارش‌های کاربر
- نمای اولیه مدیریت رستوران‌ها برای مدیر کل
- طراحی واکنش‌گرا، فارسی و راست‌چین

## ۵) مواردی که هنوز نسخه تولیدی نیستند
گفت‌وگوی پشتیبانی، کیف پول و تراکنش‌های دفترکل، کد تخفیف در checkout، بارگذاری تصاویر در Storage، مدیریت کامل کارکنان و مجوزهایشان، گردش‌کار پیک و تغییر وضعیت سفارش، گزارش مالی، اعلان‌ها و تست امنیتی نهایی هنوز پیاده‌سازی نشده‌اند. بخش‌هایی که به سیاست RLS نیاز دارند عمداً با دسترسی باز ساخته نشده‌اند.
این پروژه را به‌عنوان نسخه اولیه تست کن، نه سامانه آماده دریافت سفارش واقعی.

## ۶) نکته امنیتی مهم درباره دیتابیس فعلی
در تنظیمات قبلی، سیاست به‌روزرسانی پروفایل ممکن است به کاربر اجازه تغییر ستون `role` بدهد. قبل از انتشار عمومی، این امکان باید بسته شود. در SQL Editor این دستورات را اجرا کن:

```sql
revoke update on table public.profiles from authenticated;
grant update (full_name, phone) on table public.profiles to authenticated;
```

اگر بعداً نیاز به تغییر نقش بود، فقط از مسیر مدیریتی امن (نه از مرورگر کاربر) انجام شود.

## ۷) قبل از استفاده واقعی
- کلید `service_role` که قبلاً در گفتگو ارسال شده را فوراً rotate کن.
- RLS تمام جدول‌ها را بازبینی کن.
- سیاست‌های جداگانه مدیر رستوران، کارمند و پیک را اضافه و تست کن.
- تابع سفارش را از نظر تخفیف، موجودی، محدودیت تعداد و هم‌زمانی توسعه بده.
- ایمیل تأیید و بازیابی رمز را در Supabase تنظیم کن.
